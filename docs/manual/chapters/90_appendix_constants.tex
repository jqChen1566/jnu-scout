\chapter{Constants and Units}
\label{app:constants}

All unit conversions in \jns{} live in module-level constants, so that a
conversion shows up in exactly one place per module.  This appendix lists
them together with the module they are defined in.

\begin{notebox}[Why two Hartree-to-eV constants]
The bridge uses 27.211386245 and the SCINE calculator uses
27.211386245988 for the same conversion.  The two values differ in the
ninth significant digit; they are kept as-is because each module's value
was validated in place, and the discrepancy is far below any physical or
numerical tolerance that matters here.  Do not ``unify'' them without
re-running the equivalence checks.
\end{notebox}

\section*{The atomic-unit boundary}

Atomic units enter at exactly one place: the SCINE interface.  SCINE
stores structures in Bohr and expects Hartree / (Eh/bohr) from a
calculator, while every calculator in this package speaks ASE units (eV,
eV/\AA{}, \AA{}).  The bridge performs both conversions; nothing else in
the package should ever see a Hartree or a Bohr value.  The one historical
trap worth knowing about: the search database stores coordinates in Bohr,
so any code path that reads database geometries and feeds them to ASE
without dividing by 1.8897 stretches every molecule by that factor (a 1.08
\AA{} C--H bond becomes 2.05 \AA{} -- a broken-bond distance).  The utility
script \script{verify_bohr_units} checks this conversion with a
known-answer test.
